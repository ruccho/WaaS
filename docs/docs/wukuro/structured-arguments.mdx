# Structured Arguments

An entry point can take a record or an enum defined in C# as a parameter. The value is edited in the inspector of the script reference, and the script typically passes it, or a part of it, to a host function that takes the same C# type. A record can contain Unity objects, which are passed to the host function as the objects themselves.

## Defining types

Define the types in a C# interface with `[ComponentInterface]`, as the types used by host functions ([Extending](./extending.mdx)). A record is a `[Serializable]` struct with `[ComponentRecord]`, whose public fields with `[ComponentField]` are the fields of the record. Unity serializes the same fields, so the inspector shows them with the usual property drawers.

```csharp title="MyGameTypes.cs"
using System;
using UnityEngine;
using WaaS.ComponentModel.Binding;
using Wukuro;

namespace MyGame.Events
{
    [ComponentInterface(@"my-game:events/types")]
    public partial interface ITypes
    {
        [ComponentRecord]
        [Serializable]
        public partial struct DoorSettings
        {
            [ComponentField] public int Count;
            [ComponentField] public string Label;
            [ComponentField] public DoorKind Kind;
            [ComponentField] public ObjectOf<Transform> Target;
            [ComponentField] public Limits Limits;
        }

        [ComponentRecord]
        [Serializable]
        public partial struct Limits
        {
            [ComponentField] public float Min;
            [ComponentField] public float Max;
        }

        public enum DoorKind
        {
            Wooden,
            Iron
        }
    }

    [ComponentInterface(@"my-game:events/functions")]
    public partial interface IFunctions
    {
        [ComponentApi(@"open-door")]
        ValueTask OpenDoor(ITypes.DoorSettings settings);
    }
}
```

The types are exported to WIT as follows.

```wit
interface types {
    use wukuro:core/types.{object};

    record door-settings {
        count: s32,
        label: string,
        kind: door-kind,
        target: object,
        limits: limits,
    }

    record limits {
        min: f32,
        max: f32,
    }

    enum door-kind {
        wooden,
        iron,
    }
}
```

A field can be a primitive type, `string`, an enum or a record declared in the same interface, or `ObjectOf<T>`.

- `ObjectOf<T>` (`Wukuro`) is a reference to a Unity object of type `T`. In WIT it is the `object` resource of `wukuro:core`, so the script can pass it to functions taking `&Object`. The inspector shows it as an object field of type `T`.
- A host function receives the record with the objects in `ObjectOf<T>.Value`. As `WukuroObjects.Get<T>` does, a GameObject is converted to its component of type `T`.

## Implementing host functions

The host function takes the C# type as it is.

```csharp
private class Functions : IFunctions
{
    public Wukuro.Core.ITypes.IObjectResourceImpl Object => WukuroObjects.ResourceType;

    public ValueTask OpenDoor(ITypes.DoorSettings settings)
    {
        Transform target = settings.Target.Value;
        // ...
        return default;
    }
}
```

The implementations of the interfaces using records with `ObjectOf<T>` need the property `Object` returning `WukuroObjects.ResourceType`, as the interfaces using the `object` resource do.

## Using from Rust scripts

The Rust types of the records are generated by wit-bindgen in the game-specific crate as the other types of the interface. In addition, `#[entry]` needs a macro for each type, which gives the definition of the type, since a procedural macro cannot read the definitions of other crates. Generate the macros with `WukuroArgumentTypeExporter` (`Wukuro.Editor`).

```csharp
var source = WukuroArgumentTypeExporter.GenerateRust(typeof(MyGame.Events.ITypes), "types",
    "// generated by WukuroArgumentTypeExporter\n");
File.WriteAllText("rust/my-game/src/argument_types.rs", source);
```

The second argument is the path of the module that has the bindings of the interface, from the root of the crate. Add the generated file as a module and re-export its items from that module, so that importing a type also imports the macro of the same name.

```rust title="rust/my-game/src/lib.rs"
pub use bindings::my_game::events::functions;

mod argument_types;

pub mod types {
    pub use crate::bindings::my_game::events::types::*;
    pub use crate::argument_types::*;
}
```

:::warning
Do not include the generated file with `include!`. The macros are exported with `#[macro_export]`, and the macros expanded from another macro cannot be referred to by paths in the crate.
:::

The types can then be parameters of entry points.

```rust
use wukuro::entry;
use wukuro::types::Context;
use my_game::types::{DoorKind, DoorSettings};

#[entry]
fn open_door(cx: &Context, settings: DoorSettings, kind: DoorKind) {
    my_game::functions::open_door(settings);
}
```

Regenerate the file when the C# definitions change, in the same way as the object types ([Object Types](./object-types.mdx#generating-rust-types)).

## Using from MoonBit scripts

No additional code is needed. **Wukuro Entry Points** finds the C# type of a parameter from the package of its MoonBit bindings (`ns_pkg_iface`, generated by [MoonBit Bindings Settings](./moonbit.mdx#extending)) and its name.

```moonbit
///|
#wukuro.entry
pub fn open_door(
  _cx : @wukuro.Context,
  settings : @types.DoorSettings,
  kind : @types.DoorKind,
) -> Unit {
  @functions.open_door(settings)
}
```

## Passing values at runtime

`WukuroRuntimeArguments.AddValue` gives a value of a record or an enum from C#.

```csharp
var arguments = new WukuroRuntimeArguments()
    .AddValue("settings", new ITypes.DoorSettings { Count = 1, Label = "gate", Target = transform })
    .AddValue("kind", ITypes.DoorKind.Iron);
await runner.RunAsync(entry, variables, arguments);
```

## How it works

- The entry point of the script imports the type from the interface of the game (`use my-game:events/types.{door-settings}`). The inspector reads the `use` from the WIT of the script, finds the C# type with `WukuroArgumentTypes.Find`, and stores the value with Unity serialization of the type.
- At runtime, the value is passed with the formatter generated by WaaS for the record. The objects in `ObjectOf<T>` are passed as `object` resources owned by the script, and a host function receiving the record takes the objects out of the resources.
- In Rust, `#[entry]` calls the macro of the type, which returns the WIT definition of the type and the path of the module of its bindings. The WIT of the entry point includes the definition, and the bindings are mapped to the module with `with` of wit-bindgen.
- In MoonBit, the generator lifts the record from the flat values of the parameters.

## Limitations

- Lists, options, variants and `wukuro:core` types other than `object` cannot be fields. The fields must be of the types in the same interface.
- In MoonBit, flags cannot be parameters, and the flattened values of the parameters of an entry point must be at most 16 (a string takes two, and a record takes the sum of its fields).
- The objects are owned by the script. A Rust script moves a record to a host function, so call `clone()` of the object to keep it.
