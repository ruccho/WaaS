# Installation

## Requirements

- Unity 6000.0 or later
- [UniTask](https://github.com/Cysharp/UniTask) (`com.cysharp.unitask`)
- WaaS (`com.ruccho.waas`)
- The toolchain of the language of the scripts:
  - Rust: the Rust toolchain and the `wasm32-unknown-unknown` target, to use [Rust Importer](../unity-integration/rust.mdx)
  - MoonBit: the [MoonBit toolchain](https://www.moonbitlang.com/download) with `moon` on `PATH`, to use [MoonBit Importer](../unity-integration/moonbit.mdx)

## Adding the Unity package

Install UniTask and WaaS first, then add Wukuro by entering the following URL in `Add package from git URL...` of the Package Manager.

```
https://github.com/ruccho/WaaS.git?path=/WaaS.Unity/Packages/com.ruccho.wukuro#release
```

`#release` refers to the `release` branch, which points to the latest release. To use a specific version, specify its tag instead, such as `#v0.4.0`. Use the same version for WaaS and Wukuro.

UniTask is not declared as a dependency in `package.json` because it is not in the Unity package registry. Install it separately following [the installation of UniTask](https://github.com/Cysharp/UniTask#upm-package).

## Setting up the guest libraries

Scripts are built with the guest library of their language, which is specified in the import settings of the importer. It is convenient to put the settings in a preset ([Rust](../unity-integration/rust.mdx#using-presets), [MoonBit](../unity-integration/moonbit.mdx#using-presets)) to apply the same settings to all scripts.

:::warning
The WIT included in the guest libraries is generated from the C# definitions in the Unity package. If the versions of the Unity package and the guest libraries differ, the definitions of the functions in scripts and the host may not match and cause errors at runtime. Keep the versions the same.
:::

### Rust {#rust}

Rust scripts are built with the crates specified in **Dependencies** of the import settings of Rust Importer. Wukuro scripts require the following crates.

| Crate | Usage |
| --- | --- |
| `wukuro` | Required by all scripts. |
| `wukuro-dialog` | Required by scripts that show dialogs. |
| Game-specific crates | Required by scripts that use the features added by the game ([Extending](./extending.mdx)). |

The Wukuro crates are published on [crates.io](https://crates.io/). Specify them **via Registry** as follows.

| Name | Version Requirements |
| --- | --- |
| `wukuro` | The same version as the Unity package (e.g. `0.4.0` for the Unity package `0.4.0`) |
| `wukuro-dialog` | The same version as `wukuro` |

Enable **Componentize** and leave **WIT Directory** empty in the import settings. The WIT of a script is embedded by `#[entry]`.

#### Using workspace dependencies {#using-workspace-dependencies}

To develop a game-specific crate in the Unity project, or to manage the versions of dependencies in one place, add `[workspace.dependencies]` to `Cargo.toml` at the root of the Unity project and select **via Workspace** in Dependencies of Rust Importer.

```toml
[workspace]
members = ["Library/com.ruccho.waas/rust/crates/*", "rust/*"] # Used by WaaS
resolver = "2" # Used by WaaS

[workspace.dependencies]
wukuro = "0.4.0"
wukuro_dialog = { package = "wukuro-dialog", version = "0.4.0" }
my-game = { path = "./rust/my-game" }
```

For a dependency **via Workspace**, specify the key in `[workspace.dependencies]` as **Name**.

#### Using unpublished versions {#using-unpublished-versions}

To try changes not yet published on crates.io, the crates can be fetched from the WaaS repository with git. Cargo finds the crates in the repository by their names, so the paths in the repository do not have to be specified.

```toml
[workspace.dependencies]
wukuro = { git = "https://github.com/ruccho/WaaS.git", rev = "<commit hash>" }
wukuro_dialog = { package = "wukuro-dialog", git = "https://github.com/ruccho/WaaS.git", rev = "<commit hash>" }
```

In this case, cargo fetches the whole repository including the submodules, so the first fetch takes time. Use the Unity package of the same commit as well.

### MoonBit {#moonbit}

MoonBit scripts use the module `ruccho/wukuro`, which contains the following packages.

| Package | Usage |
| --- | --- |
| `ruccho/wukuro` | Required by all scripts. The same as the `wukuro` crate. |
| `ruccho/wukuro/dialog` | Required by scripts that show dialogs. The same as the `wukuro-dialog` crate. |
| Packages of game-specific modules | Required by scripts that use the features added by the game ([Extending](./extending.mdx)). |

Specify the module in the import settings of MoonBit Importer as follows.

- **Dependencies**: `ruccho/wukuro` with **Version** set to the same version as the Unity package (e.g. `0.4.0`). The module is published on [mooncakes.io](https://mooncakes.io/).
- **Imports**: `ruccho/wukuro` as `wukuro`, and `ruccho/wukuro/dialog` as `dialog`. For a [script package](../unity-integration/moonbit.mdx#script-packages), write them in its `moon.pkg` instead.
- **Componentize**: enabled. **WIT Directories** can be empty, because the WIT of `wukuro:core` and `wukuro:dialog` is in the `wit` directory of the module.
- **Generators**: add **Wukuro Entry Points**, which generates the exports of the entry points.

To use an unpublished version, set **Local Path** of the dependency to the directory of the module in a clone of the [WaaS repository](https://github.com/ruccho/WaaS) (`Wukuro/moonbit/wukuro`, e.g. `../WaaS/Wukuro/moonbit/wukuro` when the repository is cloned next to the Unity project), and use the Unity package of the same commit.
