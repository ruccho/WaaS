This page compares WaaS with other scripting engines and WebAssembly runtimes. The results can be reproduced with [WaaS.Benchmarks](https://github.com/ruccho/WaaS/tree/main/WaaS.Benchmarks).

## Interpreter backends

| Backend | Used when |
|---|---|
| Burst | Unity with `com.unity.burst` installed, on the platforms that Burst compiles for |
| Managed | Otherwise: .NET, and Unity without Burst |

No change of code is needed to use the Burst backend. A debugger uses a slower interpreter that executes each instruction separately.

Without Burst, IL2CPP gains less from the optimizations of the interpreter than CoreCLR does. If performance matters on IL2CPP, install `com.unity.burst`.

## Conditions

Windows 11, Intel Core i7-13700F. Unity 6000.5.8f1 with non-development IL2CPP players, .NET 10, xLua (`59bf426`, Lua 5.3), Lua-CSharp 0.5.8, wasmtime 50.0.1 and wasm3 (`28ecb9a`, built with clang). WaaS is built from the commit that added these results. Each value is the lowest of the medians of four alternating runs.

The same workloads are implemented in Rust, MoonBit and Lua, and the harnesses verify that all of them compute the same checksums. wasm3 and wasmtime run outside of .NET, so only the compute workloads are measured on them.

| Workload | Content |
|---|---|
| fib | Recursive Fibonacci number of 30 |
| sieve | Sieve of Eratosthenes up to 1,000,000 |
| mandelbrot | Mandelbrot set on a grid of 200 × 200 |
| strings | Formats, splits and hashes 20,000 strings |
| sort | Sorts 200,000 integers |
| map | Inserts 500,000 times into a hash map |

## Reading the results

- Numbers are compared on a desktop x64 CPU. Other platforms have not been measured.
- The results depend on the code that a compiler generates for a guest. For example, `map` runs the hash function of the guest in the interpreter, while Lua uses a table implemented in C.
- Performance is one of the factors in choosing an engine. WaaS also offers sandboxing and a choice of guest languages, and does not need JIT compilation.
