# Using MoonBit Importer

WaaS allows you to directly compile [MoonBit](https://www.moonbitlang.com/) code to WebAssembly by importing it as assets. A script is a single `*.mbt` file, or a MoonBit package in the project ([Script packages](#script-packages)), and it is compiled to a component by default.

:::info
To use MoonBit Importer, you need the [MoonBit toolchain](https://www.moonbitlang.com/download) (`moon` on `PATH`). The `wasm` backend (not `wasm-gc`) is used.
:::

## Import Settings

- **Script**: Specify whether to treat the source file as a script. If unchecked, the file is not compiled. A file in a directory with `moon.pkg` (a file of a MoonBit package, such as a library placed in the project) is never treated as a script.
- **Preset**: A preset of the settings below. See [Using Presets](#using-presets).
- **Dependencies**: Modules the script depends on.
  - **Name**: The name of the module, such as `ruccho/wukuro`.
  - **Version**: The version of the module on [mooncakes.io](https://mooncakes.io/). Ignored for a local module.
  - **Local Path**: The directory of the module on the local file system, relative to the root of the Unity project. Leave it empty to use mooncakes.io.
- **Imports**: Packages the script imports, with the alias used in the script (e.g. `ruccho/wukuro` as `@wukuro`). An empty alias uses the last part of the path.
- **Componentize**: Convert the WebAssembly module to a component. See [Componentization](#componentization).
- **WIT Directories**: Directories that contain the WIT packages imported by the component, each in its own subdirectory, relative to the root of the Unity project. The `wit` directories of the local modules are also used.
- **Generators**: Code generators of the entry package, provided by frameworks such as [Wukuro](../wukuro/moonbit.mdx).

:::warning
MoonBit Importer recompiles the script when the source file or the files of the local modules generated by WaaS (e.g. the [bindings](#generating-bindings)) change. Changes of other files outside of Unity's management are not detected. In that case, right-click the script and select `Reimport`. Selecting `Assets` > `Recompile MoonBit scripts for WaaS` recompiles all MoonBit scripts in the project.
:::

### Using Presets

Create a preset asset with `Create` > `WaaS` > `MoonBit Importer Preset`, and set it to the **Preset** field of the import settings to share the settings among scripts.

## How scripts are built

For each script, MoonBit Importer creates a workspace under `Library/com.ruccho.waas/moonbit/<hash>`:

- `moon.work`: the members are the module of the script and the local modules in **Dependencies**.
- `module/script`: the package of the script (a copy of the source file).
- `module/main`: the entry package, which exports the functions of the component (`cabi_realloc` and the code added by the generators).

The script is built with `moon build --target wasm --release`. Compilation errors are shown in the Unity console with the path of the source file.

:::warning
The paths of the files in the workspace are long. On Windows, place the Unity project in a directory with a short path if the build fails because of the limit of the path length.
:::

## Script packages

A directory in `Assets` with `moon.pkg` is a MoonBit package, and it is imported as a script: the `moon.pkg` asset is the component. All `*.mbt` files in the directory are the source of the script, and the packages it imports are written in `moon.pkg` instead of **Imports** of the import settings.

```text title="Assets/Scripts/Villager/moon.pkg"
import {
  "ruccho/wukuro" @wukuro,
}
```

A script package is built from a copy in its workspace, as a single `*.mbt` script is, so that the generators can add files to it. The packages belong to the **project module**, `moon.mod` at the root of the Unity project, whose source directory is `Assets`. The package `Assets/Scripts/Villager` is `<module name>/Scripts/Villager`, so the names of the directories must consist of letters, digits, `_` and `-`. When a script package is imported, MoonBit Importer creates the project module and the workspace `moon.work` at the root of the project if they do not exist, and adds the **Dependencies** of the import settings to them.

```text title="moon.mod"
name = "unity/project"

source = "Assets"

preferred_target = "wasm"

import {
  "ruccho/wukuro@0.0.0",
}
```

```text title="moon.work"
members = [
  "../WaaS/Wukuro/moonbit/wukuro",
  ".",
]
```

### Using IDE functionality

Open the root folder of the project with an IDE which supports MoonBit, and you can use its features such as code completion and diagnostics for script packages, as with Rust Importer and `Cargo.toml`. A single `*.mbt` script is built from a copy in its workspace, so these features are not available for it; use a script package to edit a script with an IDE.

It is recommended to add `moon.mod` and `moon.work` to version control, and to ignore `_build/` at the root and `pkg.generated.mbti`, which are created by the IDE.

## Componentization

When **Componentize** is enabled, the module is componentized with a world that imports the interfaces imported by the module and exports the interfaces added by the generators. The WIT packages of the imported interfaces are looked up in **WIT Directories** and the `wit` directories of the local modules. Strings are passed in UTF-16, the string encoding of MoonBit.

`println` of MoonBit imports a function that no component can provide. It is bound to a function that does nothing, as `println` of Rust is on `wasm32-unknown-unknown`.

## Generating bindings

The bindings of WIT interfaces are generated into a MoonBit module by **MoonBit Bindings Settings** (`Create` > `WaaS` > `MoonBit Bindings Settings`). They are generated after the [WIT export](../component-model/binding-generator/wit-export.mdx) of every script compilation, and only changed files are written.

- **WIT Directory**: the directory that contains the WIT packages, such as the destination of WIT Export Settings.
- **Interfaces**: the interfaces to generate the bindings of, such as `my-game:events/functions`.
- **Output Directory**: the directory to write the bindings to, which is used only by the bindings.
- **Package Path**: the package path of the output directory, such as `my-name/my-game/bindings`.
- **External Interfaces**: interfaces whose bindings are provided by other packages. The generated code refers to the given package instead of generating the interface again, so the types are shared with the other module.

The bindings of an interface `ns:pkg/iface` are generated as the package `<Package Path>/ns_pkg_iface`.

## Disabling MoonBit Importer

To disable MoonBit Importer, use `WAAS_DISABLE_MOONBIT_IMPORTER` define symbol.
