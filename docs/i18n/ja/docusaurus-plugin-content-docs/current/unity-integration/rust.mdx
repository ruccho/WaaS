# Rust Importer の使用

WaaS では、`*.rs` ファイルをアセットとしてインポートすることで直接 WebAssembly にコンパイルすることができます。

:::info
Rust Importer を利用するには [Rust ツールチェイン](https://www.rust-lang.org/ja/tools/install) と [`wasm32-unknown-unknown`](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html#building-rust-programs) ターゲットが必要です。
:::

## インポート設定

<center>
    <img src={rustImporterImage} width="400" />
</center>

- **Create Root**: ソースファイルをクレートのルートとして扱うかを指定します。チェックを外すと、ソースファイルは直接 WebAssembly にコンパイルされませんが、ほかのソースファイルからモジュールとして参照できます。
- **Dependencies**: 依存するパッケージを指定します。
  - **via Registry**: パッケージレジストリからパッケージをインストールします。
  - **via Git**: Git リポジトリからパッケージをインストールします。
- **Componentize**: WebAssembly モジュールをコンポーネントに変換します。詳しくは [コンポーネント化](#コンポーネント化) を参照してください。

### Dependency

- **Name**: パッケージ名を指定します。
- **Version Requirements**: バージョンを指定します。詳しくは [The Cargo Book](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html) を参照してください。
- **Features**: 有効化する feature を指定します。

#### via Registry 固有の項目

- **Registry** (optional): パッケージを取得するレジストリを指定します。詳しくは [The Cargo Book](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#specifying-dependencies-from-other-registries) を参照してください。

#### via Git 固有の項目

- **Git Url**: Git リポジトリの URL を指定します。
- **Branch** (optional): ブランチ名を指定します。
- **Tag** (optional): タグ名またはコミットハッシュを指定します。
- **Rev** (optional): コミットハッシュを指定します。


:::warning
Rust Importer は、ソースファイルのビルドに使われたファイルの変更を検知して、自動的に再コンパイルを行います。対象は、ソースファイル自身と、cargo がビルドの入力として出力するファイル（パスで参照するクレートのソースや、`wit_bindgen::generate!` が読み込む WIT ファイルなど）です。Unity の管理外にあるファイルは、環境設定（**Asset Pipeline**）の **Auto Refresh** が有効であれば、エディタがアクティブな間に、更新日時とサイズで変更を確認します。無効の場合は、`Assets` > `Reimport Scripts with Changed Files for WaaS` を選択すると確認します。コンパイルエラーの後は、最後に成功したビルドの入力のファイルを確認します。ただし、次の場合は変更が検知されません。

- 最後に成功したビルドの入力ではなかったファイルが作成・変更された場合（コンパイルエラーの後にクレートに追加したモジュールなど）
- レジストリや Git リポジトリのクレートが更新された場合

これらの場合は、対象のソースファイルを右クリックして `Reimport` を行うことで再コンパイルされます。  
また、`Assets` > `Recompile Rust scripts for WaaS` を選択すると、プロジェクト内のすべての Rust ソースファイルを再コンパイルします。
:::

### プリセットの利用

上記の設定を**プリセット アセット**として保存することで再利用できます。

`Create` > `WaaS` > `Rust Importer Preset` からプリセットを作成し、Rust Importer の Inspector の **Preset** 欄にセットしてください。

## IDE 機能の利用

VS Code と [rust-analyzer](https://rust-analyzer.github.io/) のような Cargo プロジェクトに対応する IDE で **Unity プロジェクトのルート**をワークスペースとして開くと、補完、定義への移動、診断などの IDE の機能を利用しながら Rust ソースファイルを編集できます。[Wukuro](../wukuro/index.mdx) のクレート、`wit_bindgen::generate!` が生成するバインディング、**Dependencies** のクレートなど、スクリプトの依存はビルド時と同様に解決されます。

これは、Rust Importer が Unity プロジェクトのルートに `Cargo.toml` を作成することによって実現しています：

```toml
[workspace]
members = ["Library/com.ruccho.waas/rust/crates/*"] # Used by WaaS
resolver = "2" # Used by WaaS

```

内部的には `Library/com.ruccho.waas/rust/crates/*` に **Create Root** として指定された各 `*.rs` をルートとするクレート群が自動生成されます。各クレートのルートは `Assets` または `Packages` 内のソースファイルそのものであるため、IDE はソースファイルを直接解析します。これらクレートの `Cargo.toml` は Rust Importer が自動的に上書きするので、手動での編集はできません。ソースファイルを削除するか **Create Root** を無効にすると、そのソースファイルのクレートは削除されます。

:::info
クレートはソースファイルのインポート時に生成されます。プロジェクトのクローン後や `Library` の削除後などは、IDE で開く前に Unity でプロジェクトを開いてください。クレートが生成されるまでは IDE がワークスペースを読み込めず、また新しいソースファイルは解析されません。
:::

### WebAssembly 向けの解析

rust-analyzer は既定ではホストのプラットフォーム向けにコードを解析しますが、Rust Importer は `wasm32-unknown-unknown` 向けにビルドします。`#[cfg(target_arch = "wasm32")]` の付いたコードなど、ホスト向けでは無効になるコードを解析するには、ワークスペースの設定（VS Code では `.vscode/settings.json`）で IDE のターゲットを指定してください：

```json title=".vscode/settings.json"
{
  "rust-analyzer.cargo.target": "wasm32-unknown-unknown"
}
```

### IDE のビルドディレクトリ

rust-analyzer はワークスペースに対して `cargo check` を実行するため、プロジェクトのルートに `target` ディレクトリが作成されます。`.gitignore` に `/target/` を追加するか、`rust-analyzer.cargo.targetDir` で rust-analyzer のビルドディレクトリを変更してください（例: `"Library/rust-analyzer"`）。Rust Importer は `Library/com.ruccho.waas/rust/target` を使用するため、これらの設定の影響を受けません。

## Rust Importer の無効化

Define Symbol として `WAAS_DISABLE_RUST_IMPORTER` を指定すると、Rust Importer が無効化されます。

## コンポーネント化

:::info
コンポーネント化については [Component Model ではじめる](../getting-started/component-model) を参照してください。
:::

**Componentize** を有効にすると、次の項目を設定できます。

- **WIT Directory**: コンポーネントのワールドを定義する WIT のディレクトリを、Unity プロジェクトのルートからの相対パスで指定します。`wit_bindgen::generate!` でビルドしたモジュールなど、モジュールがすでにコンポーネントの型を持つ場合は空にします。この場合、WIT は改めて埋め込まれません。
- **World**: WIT のワールドの名前を指定します。空の場合は自動で選択されます。

## ベストプラクティス

### バージョン管理

Unity プロジェクトのルートに作成された `Cargo.toml` および `Cargo.lock` をバージョン管理に追加することをお勧めします。

### wee_alloc の使用

[wee_alloc](https://github.com/rustwasm/wee_alloc) は、コードサイズの削減を目的とした WebAssembly 向けのアロケータです。

依存関係に `wee_alloc` を追加し、次のコードを追加します。

```rust
#[global_allocator]
static ALLOC: wee_alloc::WeeAlloc = wee_alloc::WeeAlloc::INIT;
```

### ビルド設定

Unity プロジェクトのルートに生成された `Cargo.toml` を編集して、コードサイズ最適化のためのオプションを追加できます。

```toml
## ...

[profile.release]
lto = true
codegen-units = 1
opt-level = "z"
```

:::info
現在、Rust Importer は常に `--release` プロファイルでビルドします。
:::
