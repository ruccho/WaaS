---
title: スクリプトのデバッグ
sidebar_position: 3
---

Unity エディタで実行しているスクリプトを、Debug Adapter Protocol（DAP）を通して、VS Code からブレークポイントとステップ実行でデバッグできます。

## 準備

1. Unity で **Assets > Enable Debugger for WaaS** を有効にします。エディタはローカルホストのポート 4711（`WaaSDebugger.Port`）で待ち受けます。
2. Rust のスクリプトでは、**Assets > Build Rust Scripts with Debug Information for WaaS** を有効にします。スクリプトは、命令とソースの行を対応付ける DWARF の行番号表を含めて再ビルドされます。この設定はユーザーごとであり、既定では無効です。
3. VS Code に、リポジトリの `vscode-waas` の拡張をインストールし、`launch.json` に次の構成を追加します。

```json
{
  "type": "waas",
  "request": "attach",
  "name": "Attach to Unity (WaaS)",
  "port": 4711
}
```

デバッガが接続した後に開始したスクリプトがデバッグの対象になります。スクリプトが停止しても、ゲームとエディタは止まらず、スクリプトだけが待機します。

## 機能

- Rust のスクリプトのソースファイルへのブレークポイント。命令のない行（最適化で消えた行など）のブレークポイントは、命令のある次の行に移ります。
- ステップ実行（ステップオーバー、ステップイン、ステップアウト）。ステップ実行は Unity のプロジェクト内のファイルの行でのみ止まり、標準ライブラリなどのライブラリは飛ばします。
- スクリプトの一時停止。
- スタックフレームと、WebAssembly のローカル変数、オペランドスタック、グローバル。

## 制限

- 値は、ソースの言語の変数ではなく、WebAssembly の値として表示されます。
- 最適化してビルドしたスクリプト（Rust Importer は release プロファイルでビルドします）は、行に対応付けられる命令が少なく、ステップ実行で行が前後することがあります。
- デバッガの接続中は、スクリプトの実行が数倍遅くなります。
- MoonBit のスクリプトには行番号表がありません。停止した後にスタックフレームと値を確認できます。
- エディタのドメインがリロードされると、クライアントの接続は切れます。
