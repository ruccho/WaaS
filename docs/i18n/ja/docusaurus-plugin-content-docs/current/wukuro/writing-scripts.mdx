# スクリプトの記述

Wukuro のスクリプトは Rust または MoonBit で記述します。どちらの言語でも同じ機能を使え、両方の言語のスクリプトを 1 つのプロジェクトで併用でき、実行の方法も同じです（[スクリプトの実行](./running-scripts.mdx)）。事前に、使う言語のゲスト側のライブラリを設定してください（[導入](./installation.mdx)）。ほかの言語も、手間はかかりますが WIT を介して利用できます（[ほかの言語の利用](./other-languages.mdx)）。

| | Rust | MoonBit |
| --- | --- | --- |
| インポーター | [Rust Importer](../unity-integration/rust.mdx)（`*.rs`） | [MoonBit Importer](../unity-integration/moonbit.mdx)（`*.mbt`、または[スクリプトパッケージ](../unity-integration/moonbit.mdx#script-packages)） |
| ゲスト側のライブラリ | クレート `wukuro` と `wukuro-dialog` | モジュール `ruccho/wukuro`（パッケージ `ruccho/wukuro` と `ruccho/wukuro/dialog`） |
| エントリポイント | `#[entry]` | `#wukuro.entry` |

## エントリポイント {#entry-points}

エントリポイントとして指定した関数が、スクリプトから公開されます。1 つのファイルに複数のエントリポイントを置くことができ、同じファイル内の定数や関数を共有できます。

<Tabs groupId="language">
<TabItem value="rust" label="Rust">

関数に `#[entry]` を付けると、その関数がエントリポイントになります。

```rust
use wukuro::entry;
use wukuro::functions::*;
use wukuro::types::Context;

const GREETING: &str = "こんにちは";

fn greet(name: &str) {
    log(&format!("{GREETING}、{name}"));
}

#[entry]
fn morning(cx: &Context) {
    greet("朝の人");
}

#[entry]
fn night(cx: &Context) {
    greet("夜の人");
}
```

</TabItem>
<TabItem value="moonbit" label="MoonBit">

属性 `#wukuro.entry` を付けた公開の関数がエントリポイントになります。関数は `pub` で、`Unit` を返す必要があります。

```moonbit
///|
let greeting = "こんにちは"

///|
fn greet(name : String) -> Unit {
  @wukuro.log("\{greeting}、\{name}")
}

///|
#wukuro.entry
pub fn morning(_cx : @wukuro.Context) -> Unit {
  greet("朝の人")
}

///|
#wukuro.entry
pub fn night(_cx : @wukuro.Context) -> Unit {
  greet("夜の人")
}
```

</TabItem>
</Tabs>

エントリポイント `foo_bar` は、コンポーネントのインターフェース `wukuro-entry:foo-bar/entry` の関数 `run` として公開されます。エントリポイントの名前は、関数名を kebab-case にしたもの（`_` を `-` に置き換えたもの）です（[WIT リファレンス](./reference.mdx#entry-points)）。

### 引数 {#parameters}

エントリポイントの最初の引数はコンテキストです。2 番目以降の引数には、次の型を使えます。

| WIT の型 | Rust の型 | MoonBit の型 | インスペクタでの入力 |
| --- | --- | --- | --- |
| `bool` | `bool` | `Bool` | チェックボックス |
| `s8` 〜 `u64` | `i8`、`i16`、`i32`、`i64`、`u8`、`u16`、`u32`、`u64` | `Byte`（`u8`）、`Int16`、`UInt16`、`Int`、`UInt`、`Int64`、`UInt64`（`s8` に対応する型はありません） | 整数 |
| `f32`、`f64` | `f32`、`f64` | `Float`、`Double` | 小数 |
| `char` | `char` | `Char` | 文字 |
| `string` | `String` | `String` | 文字列 |
| `borrow<action>` | `&wukuro::types::Action` | `@wukuro.Action` | UnityEvent |
| `borrow<object>` | `&wukuro::types::Object` | `@wukuro.Object` | 任意の `UnityEngine.Object` |
| `borrow<object>` | `&wukuro::ObjectOf<T>` | `@wukuro.ObjectOf[T]` | 型 `T` のオブジェクト（[オブジェクトの型](./object-types.mdx)） |
| `record`、`enum` | C# で定義した record または enum | C# で定義した record または enum | C# の型のフィールド（[構造化された引数](./structured-arguments.mdx)） |

引数の値は、インスペクタで設定した値や C# から渡した値と、引数名を kebab-case にした名前（`camera_target` であれば `camera-target`）で対応付けられます。

`Action` は、`run()` で呼び出せる C# の処理です。インスペクタでは UnityEvent として設定します。

## コンテキスト {#context}

コンテキストから、引数や変数を取得できます。

<Tabs groupId="language">
<TabItem value="rust" label="Rust">

```rust
use wukuro::types::Argument;

#[entry]
fn counter(cx: &Context) {
    // 変数を取得して設定する
    let variable = cx.get_variable("count");
    let count = match variable.get() {
        Some(Argument::TyS32(value)) => value,
        _ => 0,
    };
    variable.set(Argument::TyS32(count + 1));
    log(&format!("count: {}", count + 1));
}
```

</TabItem>
<TabItem value="moonbit" label="MoonBit">

```moonbit
///|
#wukuro.entry
pub fn counter(cx : @wukuro.Context) -> Unit {
  // 変数を取得して設定する
  let variable = cx.get_variable("count")
  let count = match variable.get() {
    Some(TyS32(value)) => value
    _ => 0
  }
  variable.set(TyS32(count + 1))
  @wukuro.log("count: \{count + 1}")
}
```

</TabItem>
</Tabs>

- `get_argument(name)`: 引数の値を名前で取得します。エントリポイントの引数として宣言していない値も取得できます。
- `get_variable(name)`: 変数を取得します。変数の保存先は、スクリプトを実行する C# 側が決めます（[スクリプトの実行](./running-scripts.mdx#variables)）。

値は `Argument`（Rust では `wukuro::types::Argument`、MoonBit では `@wukuro.Argument`）で表されます。`TyBool`、`TyS32`、`TyF32`、`TyString`、`TyAction`、`TyObject` などのケースがあります。

:::info
スクリプトが取得したリソース（`Variable` など）は、Rust ではスコープの終わりに解放されます。MoonBit では、エントリポイントの実行が終わったときに解放されます。`drop()` で早めに解放することもできます。
:::

## 関数 {#functions}

`wukuro:core` は次の関数を提供します（Rust では `wukuro::functions`、MoonBit では `@wukuro`）。

| 関数 | 説明 |
| --- | --- |
| `log(message)` | Unity のコンソールにログを出力します。 |
| `delay(duration, update_mode)` | 指定した秒数だけ待機します。`update_mode` は `UpdateModeKind` の `Scaled`（`Time.timeScale` の影響を受ける）、`Unscaled`（影響を受けない）、`Realtime`（実時間）のいずれかです（MoonBit では `SCALED`、`UNSCALED`、`REALTIME`）。 |
| `delay_frame(num_frames)` | 指定したフレーム数だけ待機します。 |
| `schedule(action, delay, update_mode)` | `delay` 秒後に `action` を実行します。完了を待たずに戻ります。戻り値の `Task` で、完了を待つ（`wait()`）ことや、完了したかを確認する（`is_completed()`）ことができます。 |

:::info
スクリプト内の関数の呼び出しは、ホスト側の処理が完了するまで戻りません。待機やカットシーンの終了を待つ処理を、通常の関数の呼び出しとして順に記述できます。
:::

## テキスト {#texts}

プレイヤーに表示するテキストは `Text` で表されます。スクリプトに直接書いた文字列（`Plain`）と、ローカライズされたテキストの参照（`Localized`）の 2 種類があります。テキストを受け取る関数は `IntoText` を受け取るため、文字列と `Text` のどちらも渡せます。ローカライズされたテキストを実際の文字列にする方法は、ホスト側の実装が決めます。

ローカライズされたテキストは、テーブル名とキーから作ります。原文も任意で書けます。原文は実行時には使われず、スクリプトの読みやすさのためのものです。

<Tabs groupId="language">
<TabItem value="rust" label="Rust">

```rust
use wukuro::{l10n, IntoText};

let greeting = l10n!("Dialogs", "greeting", "こんにちは");
let plain = "こんにちは".into_text();
```

</TabItem>
<TabItem value="moonbit" label="MoonBit">

```moonbit
let greeting = @wukuro.l10n("Dialogs", "greeting", source="こんにちは")
```

</TabItem>
</Tabs>

## ダイアログ {#dialogs}

`wukuro:dialog` は、ダイアログにメッセージや選択肢を表示します（Rust ではクレート `wukuro-dialog`、MoonBit ではパッケージ `ruccho/wukuro/dialog`）。ダイアログの表示は、ホスト側の実装（`IDialogModule`）が行います（[機能の追加](./extending.mdx#implementing-dialogs)）。

<Tabs groupId="language">
<TabItem value="rust" label="Rust">

```rust
use wukuro::entry;
use wukuro::types::Context;
use wukuro_dialog::functions::*;
use wukuro_dialog::*;

#[entry]
fn shopkeeper(cx: &Context) {
    let dialog = get_dialog_module(cx);
    let d = DialogSession::new(&dialog, None);

    d.msg::<Shopkeeper>("いらっしゃい！");
    d.show(MessageInfo::new::<Shopkeeper>("何か買っていくかい？").face(&ShopkeeperFace::Smile));

    match d.opts(["買う", "やめる"]) {
        0 => d.msg::<Shopkeeper>("まいど！"),
        _ => d.msg::<Shopkeeper>("また来てくれよな"),
    }
}
```

</TabItem>
<TabItem value="moonbit" label="MoonBit">

```moonbit
///|
#wukuro.entry
pub fn shopkeeper(cx : @wukuro.Context) -> Unit {
  let module = @dialog.get_dialog_module(cx)
  @dialog.dialog(module, fn(d) {
    d.msg(shopkeeper, "いらっしゃい！")
    d.show(@dialog.message(shopkeeper, "何か買っていくかい？").face("smile"))
    match d.opts(["買う", "やめる"]) {
      0 => d.msg(shopkeeper, "まいど！")
      _ => d.msg(shopkeeper, "また来てくれよな")
    }
  })
}
```

</TabItem>
</Tabs>

### ダイアログのセッション {#dialog-sessions}

ダイアログはセッションの間だけ開かれます。Rust では `DialogSession::new(&dialog, provider)` で開き、セッションが破棄されると閉じます。MoonBit では `@dialog.dialog(module, provider?, f)` で開き、`f` を実行してから閉じます。provider には、ホストが解釈するダイアログの種類を指定できます。

- `msg(speaker, text)`（Rust では `msg::<T>(text)`）: 話者の既定の表情でメッセージを表示し、プレイヤーが進めるまで待機します。
- `show(message)`: 設定したメッセージを表示します。
- `opts(options)`: 選択肢を表示し、選ばれた選択肢の番号を返します。

### メッセージの設定 {#configuring-messages}

メッセージは話者とテキストから作ります（Rust では `MessageInfo::new::<T>(text)`、MoonBit では `@dialog.message(speaker, text)`）。ほかの設定は、メソッドをつなげて変更します。

<Tabs groupId="language">
<TabItem value="rust" label="Rust">

```rust
d.show(
    MessageInfo::new::<Shopkeeper>("……")
        .face(&ShopkeeperFace::Sad) // 表情
        .auto(true) // 入力を待たずに進む
        .forbid_skip(true) // スキップを禁止する
        .forbid_accel(true) // 早送りを禁止する
        .style("whisper"), // ホストが解釈する表示のスタイル
);
```

</TabItem>
<TabItem value="moonbit" label="MoonBit">

```moonbit
// 表情、入力を待たずに進む、スキップと早送りの禁止、ホストが解釈する表示のスタイル
let message = @dialog.message(shopkeeper, "……").face("sad").auto(true)
d.show(message.forbid_skip(true).forbid_accel(true).style("whisper"))
```

</TabItem>
</Tabs>

### 話者と表情 {#speakers-and-faces}

話者は `DialogSpeaker` を実装した型で、表情は `DialogFace` を実装した型で表します。名前は文字列としてホストに渡され、ホストが対応する話者と表情を表示します。

<Tabs groupId="language">
<TabItem value="rust" label="Rust">

```rust
pub struct Shopkeeper;

impl DialogSpeaker for Shopkeeper {
    type FaceKind = ShopkeeperFace;

    fn get_name() -> String {
        "shopkeeper".to_string()
    }
}

#[derive(Default)]
pub enum ShopkeeperFace {
    #[default]
    Normal,
    Smile,
    Sad,
}

impl DialogFace for ShopkeeperFace {
    fn get_name(&self) -> String {
        match self {
            ShopkeeperFace::Normal => "normal",
            ShopkeeperFace::Smile => "smile",
            ShopkeeperFace::Sad => "sad",
        }
        .to_string()
    }
}
```

ナレーションなど、話者のいないメッセージには `NoSpeaker` を使います。

</TabItem>
<TabItem value="moonbit" label="MoonBit">

話者は `@dialog.DialogSpeaker` の `name` と `default_face` を実装します。`String` は `@dialog.DialogFace` を実装しています。

```moonbit
///|
pub(all) enum Shopkeeper {
  Shopkeeper
}

///|
pub impl @dialog.DialogSpeaker for Shopkeeper with name(_) {
  "shopkeeper"
}

///|
pub impl @dialog.DialogSpeaker for Shopkeeper with default_face(_) {
  "normal"
}

///|
let shopkeeper : Shopkeeper = Shopkeeper
```

ナレーションなど、話者のいないメッセージには `@dialog.no_speaker` を使います。

</TabItem>
</Tabs>

話者の一覧をゲームのデータから生成してゲームのゲスト側のライブラリに含めると、話者や表情の名前の誤りをコンパイル時に検出できます（[ゲームのデータからコードを生成する](./extending.mdx#generating-code-from-the-data-of-the-game)）。

### フェード {#fades}

セッションの間、画面をフェードします。Rust では `FadeSession::new(&dialog, duration_in, duration_out)` でフェードし、セッションが破棄されると元に戻ります。MoonBit では `@dialog.fade(module, duration_in?, duration_out?, f)` で、`f` の間だけ画面をフェードします。

## 失敗 {#failures}

失敗するとスクリプトは停止し、メッセージは WebAssembly のスタックトレースとともに `WukuroPanicException` としてホストに報告されます。

- Rust: パニック（`panic!`、`unwrap()` など）は、メッセージと位置を報告します。
- MoonBit: `abort(message)` と `@wukuro.fail(message)` は、メッセージを報告します。MoonBit のコンパイラは `abort` のメッセージを捨てるため、**Wukuro Entry Points** が、ビルドするスクリプトのコピーで `abort` を置き換えます。`@wukuro.fail` はライブラリの中でも使えます。`panic()` や範囲外のインデックスなどのほかの失敗は、メッセージなしでスクリプトを停止します。
