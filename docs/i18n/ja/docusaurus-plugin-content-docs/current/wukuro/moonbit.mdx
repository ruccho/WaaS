# MoonBit でのスクリプトの記述

Wukuro のスクリプトは [MoonBit](https://www.moonbitlang.com/) でも記述できます。MoonBit のスクリプトは、エントリポイント、引数、コンテキスト、関数、テキスト、ダイアログ、オブジェクトの型について、Rust のスクリプトと同じ機能を持ちます。両方の言語のスクリプトを 1 つのプロジェクトで併用でき、実行の方法も同じです（[スクリプトの実行](./running-scripts.mdx)）。

## 準備 {#setting-up}

MoonBit のスクリプトは [MoonBit Importer](../unity-integration/moonbit.mdx) でインポートします。スクリプトは 1 つの `*.mbt` ファイル、または IDE で編集できる[スクリプトパッケージ](../unity-integration/moonbit.mdx#script-packages)です。`moon` が `PATH` 上にあるように [MoonBit のツールチェイン](https://www.moonbitlang.com/download)をインストールしてください。

Wukuro のゲスト用のライブラリは、MoonBit のモジュール `ruccho/wukuro` です。次のパッケージを含みます。

| パッケージ | 用途 |
| --- | --- |
| `ruccho/wukuro` | すべてのスクリプトで必要です。`wukuro` クレートに相当します。 |
| `ruccho/wukuro/dialog` | ダイアログを表示するスクリプトで必要です。`wukuro-dialog` クレートに相当します。 |

モジュールは [WaaS のリポジトリ](https://github.com/ruccho/WaaS)の `Wukuro/moonbit/wukuro` にあります。インポート設定（[プリセット](../unity-integration/moonbit.mdx#using-presets)に設定すると便利です）に次のように指定します。

- **Dependencies**: `ruccho/wukuro` を追加し、**Local Path** にモジュールのディレクトリを指定します（例: リポジトリを Unity プロジェクトの隣に clone した場合は `../WaaS/Wukuro/moonbit/wukuro`）。
- **Imports**: `ruccho/wukuro` を `wukuro`、`ruccho/wukuro/dialog` を `dialog` として追加します。スクリプトパッケージでは、代わりにその `moon.pkg` に記述します。
- **Componentize**: 有効にします。`wukuro:core` と `wukuro:dialog` の WIT はモジュールの `wit` ディレクトリにあるため、**WIT Directories** は空で構いません。
- **Generators**: **Wukuro Entry Points** を追加します。

:::warning
モジュールの WIT は、Unity パッケージの C# の定義から生成されています。Unity パッケージと同じバージョンのモジュールを使用してください。
:::

## エントリポイント

公開の関数に属性 `#wukuro.entry` を付けると、その関数がエントリポイントになります。1 つのファイルに複数のエントリポイントを置くことができ、同じファイル内の定数や関数を共有できます。

```moonbit
///|
let greeting = "Hello"

///|
fn greet(name : String) -> Unit {
  @wukuro.log("\{greeting}, \{name}")
}

///|
#wukuro.entry
pub fn morning(_cx : @wukuro.Context) -> Unit {
  greet("early bird")
}

///|
#wukuro.entry
pub fn night(_cx : @wukuro.Context) -> Unit {
  greet("night owl")
}
```

Rust と同じく、エントリポイント `foo_bar` はインターフェース `wukuro-entry:foo-bar/entry` の関数 `run` として export されます。エントリポイントは `pub` で、`Unit` を返す必要があります。

### 引数

エントリポイントの最初の引数は `@wukuro.Context` です。それ以降の引数には次の型を使用できます。

| MoonBit の型 | WIT の型 | インスペクタでの入力 |
| --- | --- | --- |
| `Bool` | `bool` | チェックボックス |
| `Byte`、`Int16`、`UInt16`、`Int`、`UInt`、`Int64`、`UInt64` | `u8`、`s16`、`u16`、`s32`、`u32`、`s64`、`u64` | 整数 |
| `Float`、`Double` | `f32`、`f64` | 小数 |
| `Char` | `char` | 文字 |
| `String` | `string` | 文字列 |
| `@wukuro.Action` | `borrow<action>` | UnityEvent |
| `@wukuro.Object` | `borrow<object>` | 任意の `UnityEngine.Object` |
| `@wukuro.ObjectOf[T]` | `borrow<object>` | 型 `T` のオブジェクト（[オブジェクトの型](#object-types)） |
| C# で定義したレコードや列挙型 | `record`, `enum` | C# の型のフィールド（[構造化された引数](./structured-arguments.mdx)） |

MoonBit には `s8` に対応する型がありません。引数の値は、Rust と同じく kebab-case の引数名で対応付けられます。

## コンテキストと関数

コンテキスト、値、関数は Rust と同じです（[スクリプトの記述](./writing-scripts.mdx)）。

```moonbit
///|
#wukuro.entry
pub fn counter(cx : @wukuro.Context) -> Unit {
  let variable = cx.get_variable("count")
  let count = match variable.get() {
    Some(TyS32(value)) => value
    _ => 0
  }
  variable.set(TyS32(count + 1))
  @wukuro.log("count: \{count + 1}")
}
```

`Variable` など、スクリプトが取得した resource は、Rust でスコープの終わりに破棄されるのと同じく、エントリポイントの実行の終了時に破棄されます。早く解放する場合は `drop()` を呼んでください。

`ruccho/wukuro` は、関数 `log`、`delay`、`delay_frame`、`schedule` と、型 `Context`、`Variable`、`Action`、`Task`、`Object`、`Argument`、`Text`、`TextId`、`UpdateModeKind` を提供します。

## テキスト

ローカライズされたテキストは `@wukuro.l10n(table, key, source?)` で作成します。テキストを受け取る関数は `IntoText` を受け取り、`String` と `Text` がこれを実装しています。

```moonbit
let greeting = @wukuro.l10n("Dialogs", "greeting", source="Hello")
```

## ダイアログ

```moonbit
///|
#wukuro.entry
pub fn shopkeeper(cx : @wukuro.Context) -> Unit {
  let module = @dialog.get_dialog_module(cx)
  @dialog.dialog(module, fn(d) {
    d.msg(shopkeeper, "Welcome!")
    d.show(@dialog.message(shopkeeper, "Would you like to buy something?").face("smile"))
    match d.opts(["Buy", "Leave"]) {
      0 => d.msg(shopkeeper, "Thank you!")
      _ => d.msg(shopkeeper, "Come again!")
    }
  })
}
```

- `@dialog.dialog(module, provider?, f)` はダイアログを開き、`f` を実行してからダイアログを閉じます。Rust の `DialogSession` が破棄されるときに閉じるのと同じです。
- `msg(speaker, text)`、`show(message)`、`opts(options)` は Rust と同じです。
- `@dialog.message(speaker, text)` はメッセージを作成し、メソッド `face`、`auto`、`forbid_skip`、`forbid_accel`、`style` で設定を変更します。
- `@dialog.fade(module, duration_in?, duration_out?, f)` は `f` の間、画面をフェードします。

話者は `@dialog.DialogSpeaker`（`name` と `default_face`）を実装する型の値で、表情は `@dialog.DialogFace` を実装する値（`String` が実装しています）です。話者のないメッセージには `@dialog.no_speaker` を使います。

```moonbit
///|
pub(all) enum Shopkeeper {
  Shopkeeper
}

///|
pub impl @dialog.DialogSpeaker for Shopkeeper with name(_) {
  "shopkeeper"
}

///|
pub impl @dialog.DialogSpeaker for Shopkeeper with default_face(_) {
  "normal"
}

///|
let shopkeeper : Shopkeeper = Shopkeeper
```

## 失敗

`abort(message)` はスクリプトを停止し、Rust のスクリプトの panic と同じく、メッセージを WebAssembly のスタックトレースとともに `WukuroPanicException` としてホストに報告します。MoonBit のコンパイラは `abort` のメッセージを捨てるため、**Wukuro Entry Points** は、ビルドされるスクリプトのコピーで `abort` を置き換えます。`@wukuro.fail(message)` も同じ動作をし、ライブラリの中でも使用できます。`panic()` や範囲外のインデックスなど、それ以外の失敗では、メッセージなしでスクリプトが停止します。

## オブジェクトの型 {#object-types}

`ObjectOf[T]` のマーカー型は、属性 `#wukuro.object_type("<C# の型名>")` を付けた構造体です。

```moonbit
///|
#wukuro.object_type("UnityEngine.Transform, UnityEngine.CoreModule")
pub struct Transform {}

///|
#wukuro.entry
pub fn look(_cx : @wukuro.Context, target : @wukuro.ObjectOf[Transform]) -> Unit {
  ignore(target.object())
}
```

`WukuroObjectType` で宣言した型のマーカー型は、Rust 用の `GenerateRust` と同じく `WukuroObjectTypeExporter.GenerateMoonBit` で生成できます（[オブジェクトの型](./object-types.mdx)）。マーカー型は、スクリプト内と、スクリプトが依存するローカルのモジュール内のどちらにも置けます。

## 拡張 {#extending}

ゲーム固有のモジュールは、ゲーム固有のクレート（[拡張](./extending.mdx)）と同じ手順で、書き出した WIT から MoonBit のバインディングを生成して作成します。

1. ゲームの WIT を、`wukuro:core` も含めてモジュールの `wit` ディレクトリに書き出します（WIT Export Settings）。
2. [MoonBit Bindings Settings](../unity-integration/moonbit.mdx#generating-bindings) でバインディングをモジュールに生成します。**External Interfaces** に `wukuro:core/types` とパッケージ `ruccho/wukuro/bindings/wukuro_core_types` を追加し、`Context`、`Object` などの型を `ruccho/wukuro` と共有します。
3. 必要に応じてモジュールに補助のコードを追加し、スクリプトの **Dependencies** にモジュールを、**Imports** にパッケージを追加します。

C# の定義が変更されると、WIT とバインディングが再度書き出され、スクリプトが再インポートされます。
