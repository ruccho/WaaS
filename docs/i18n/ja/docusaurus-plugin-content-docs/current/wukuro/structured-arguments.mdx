# 構造化された引数

エントリポイントは、C# で定義したレコードや列挙型を引数として受け取れます。値はスクリプト参照のインスペクターで編集し、スクリプトはその値やその一部を、同じ C# の型を受け取るホスト関数に渡すのが典型的な使い方です。レコードには Unity のオブジェクトを含められ、ホスト関数にはオブジェクトそのものとして渡されます。

## 型の定義

型は、ホスト関数で使う型と同じく、`[ComponentInterface]` を付与した C# のインターフェース内に定義します（[拡張](./extending.mdx)）。レコードは `[ComponentRecord]` を付与した `[Serializable]` な構造体で、`[ComponentField]` を付与した public なフィールドがレコードのフィールドになります。Unity も同じフィールドをシリアライズするため、インスペクターでは通常のプロパティドロワーで表示されます。

```csharp title="MyGameTypes.cs"
using System;
using UnityEngine;
using WaaS.ComponentModel.Binding;
using Wukuro;

namespace MyGame.Events
{
    [ComponentInterface(@"my-game:events/types")]
    public partial interface ITypes
    {
        [ComponentRecord]
        [Serializable]
        public partial struct DoorSettings
        {
            [ComponentField] public int Count;
            [ComponentField] public string Label;
            [ComponentField] public DoorKind Kind;
            [ComponentField] public ObjectOf<Transform> Target;
            [ComponentField] public Limits Limits;
        }

        [ComponentRecord]
        [Serializable]
        public partial struct Limits
        {
            [ComponentField] public float Min;
            [ComponentField] public float Max;
        }

        public enum DoorKind
        {
            Wooden,
            Iron
        }
    }

    [ComponentInterface(@"my-game:events/functions")]
    public partial interface IFunctions
    {
        [ComponentApi(@"open-door")]
        ValueTask OpenDoor(ITypes.DoorSettings settings);
    }
}
```

これらの型は次の WIT としてエクスポートされます。

```wit
interface types {
    use wukuro:core/types.{object};

    record door-settings {
        count: s32,
        label: string,
        kind: door-kind,
        target: object,
        limits: limits,
    }

    record limits {
        min: f32,
        max: f32,
    }

    enum door-kind {
        wooden,
        iron,
    }
}
```

フィールドの型には、プリミティブ型、`string`、同じインターフェースに宣言した列挙型やレコード、`ObjectOf<T>` を使えます。

- `ObjectOf<T>`（`Wukuro`）は型 `T` の Unity のオブジェクトへの参照です。WIT では `wukuro:core` の `object` リソースになるため、スクリプトは `&Object` を受け取る関数にそのまま渡せます。インスペクターでは型 `T` のオブジェクトフィールドとして表示されます。
- ホスト関数が受け取るレコードでは、オブジェクトは `ObjectOf<T>.Value` に入っています。`WukuroObjects.Get<T>` と同じく、GameObject は型 `T` のコンポーネントに変換されます。

## ホスト関数の実装

ホスト関数は C# の型をそのまま受け取ります。

```csharp
private class Functions : IFunctions
{
    public Wukuro.Core.ITypes.IObjectResourceImpl Object => WukuroObjects.ResourceType;

    public ValueTask OpenDoor(ITypes.DoorSettings settings)
    {
        Transform target = settings.Target.Value;
        // ...
        return default;
    }
}
```

`ObjectOf<T>` を含むレコードを使うインターフェースの実装には、`object` リソースを使うインターフェースと同じく、`WukuroObjects.ResourceType` を返すプロパティ `Object` が必要です。

## Rust のスクリプトから使う

レコードの Rust の型は、インターフェースのほかの型と同じく、ゲーム固有のクレート内で wit-bindgen が生成します。これに加えて、手続きマクロはほかのクレートの定義を読めないため、`#[entry]` には型の定義を与えるマクロが型ごとに必要です。このマクロは `WukuroArgumentTypeExporter`（`Wukuro.Editor`）で生成します。

```csharp
var source = WukuroArgumentTypeExporter.GenerateRust(typeof(MyGame.Events.ITypes), "types",
    "// generated by WukuroArgumentTypeExporter\n");
File.WriteAllText("rust/my-game/src/argument_types.rs", source);
```

2 番目の引数は、インターフェースのバインディングを持つモジュールの、クレートのルートからのパスです。生成したファイルをモジュールとして追加し、その項目をこのモジュールから再エクスポートします。これにより、型をインポートすると同名のマクロもインポートされます。

```rust title="rust/my-game/src/lib.rs"
pub use bindings::my_game::events::functions;

mod argument_types;

pub mod types {
    pub use crate::bindings::my_game::events::types::*;
    pub use crate::argument_types::*;
}
```

:::warning
生成したファイルを `include!` で取り込まないでください。マクロは `#[macro_export]` でエクスポートされており、ほかのマクロから展開されたマクロはクレート内のパスで参照できません。
:::

これで、型をエントリポイントの引数にできます。

```rust
use wukuro::entry;
use wukuro::types::Context;
use my_game::types::{DoorKind, DoorSettings};

#[entry]
fn open_door(cx: &Context, settings: DoorSettings, kind: DoorKind) {
    my_game::functions::open_door(settings);
}
```

C# の定義が変わったときは、オブジェクトの型と同じ方法でファイルを生成し直します（[オブジェクトの型](./object-types.mdx#generating-the-types-of-scripts)）。

## MoonBit のスクリプトから使う

追加のコードは必要ありません。**Wukuro Entry Points** は、引数の型の C# の型を、その MoonBit のバインディングのパッケージ（[MoonBit Bindings Settings](./extending.mdx#creating-a-moonbit-module) が生成する `ns_pkg_iface`）と型の名前から見つけます。

```moonbit
///|
#wukuro.entry
pub fn open_door(
  _cx : @wukuro.Context,
  settings : @types.DoorSettings,
  kind : @types.DoorKind,
) -> Unit {
  @functions.open_door(settings)
}
```

## 実行時に値を渡す

`WukuroRuntimeArguments.AddValue` で、レコードや列挙型の値を C# から与えられます。

```csharp
var arguments = new WukuroRuntimeArguments()
    .AddValue("settings", new ITypes.DoorSettings { Count = 1, Label = "gate", Target = transform })
    .AddValue("kind", ITypes.DoorKind.Iron);
await runner.RunAsync(entry, variables, arguments);
```

## 仕組み {#how-it-works}

- スクリプトのエントリポイントは、ゲームのインターフェースから型をインポートします（`use my-game:events/types.{door-settings}`）。インスペクターはスクリプトの WIT からこの `use` を読み、`WukuroArgumentTypes.Find` で C# の型を見つけ、その型の Unity のシリアライズで値を保存します。
- 実行時には、WaaS がレコードに対して生成したフォーマッターで値が渡されます。`ObjectOf<T>` のオブジェクトは、スクリプトが所有する `object` リソースとして渡され、レコードを受け取ったホスト関数はリソースからオブジェクトを取り出します。
- Rust では、`#[entry]` が型のマクロを呼び出し、マクロは型の WIT の定義とバインディングのモジュールのパスを返します。エントリポイントの WIT はこの定義を含み、バインディングは wit-bindgen の `with` でそのモジュールに対応付けられます。
- MoonBit では、ジェネレーターが引数のフラットな値からレコードを組み立てます。

## 制限

- リスト、オプション、バリアント、`object` 以外の `wukuro:core` の型はフィールドにできません。フィールドの型は同じインターフェースの型である必要があります。
- MoonBit では、フラグ型は引数にできず、エントリポイントの引数をフラットにした値は 16 個以下である必要があります（文字列は 2 個、レコードはフィールドの合計を使います）。
- オブジェクトはスクリプトが所有します。Rust のスクリプトはレコードをホスト関数にムーブするため、オブジェクトを残すにはオブジェクトの `clone()` を呼び出します。
