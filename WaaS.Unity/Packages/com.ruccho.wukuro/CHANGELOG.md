# Changelog

Wukuro is released together with WaaS with the same version. The Unity package and the crates `wukuro`, `wukuro-macro` and `wukuro-dialog` of the same version are used together.

## [Unreleased]

- Scripts in MoonBit, with the MoonBit module `ruccho/wukuro` (`Wukuro/moonbit/wukuro`) and the generator of entry points for MoonBit Importer.
- Panics of Rust scripts are reported to the host as `WukuroPanicException` with the message. Scripts built with this version of the crates import `wukuro:core/functions.panic`, so they require the Unity package of the same version.
- Records and enums defined in C# (`[ComponentRecord]` structs and enums in a `[ComponentInterface]`) can be parameters of entry points, edited in the inspector and passed on to host functions taking the same C# types. `ObjectOf<T>` references Unity objects in the records. In Rust, `#[entry]` uses the macros generated by `WukuroArgumentTypeExporter.GenerateRust`; in MoonBit, the generator of entry points finds the C# types from the MoonBit bindings. Values are given at runtime with `WukuroRuntimeArguments.AddValue`, and `IArguments.TryGetValue` is added with a default implementation.
- `WukuroEntryPoints.CreateDefaultArguments` creates the arguments of an entry point with the default values, and `WukuroClock` makes the waits of the scripts replaceable (`WukuroClock.Immediate` completes them on the next frame), so that scripts can be run in tests.
- Scripts no longer need to depend on `wit-bindgen`. `#[entry]` uses `wit-bindgen` re-exported by `wukuro`.
